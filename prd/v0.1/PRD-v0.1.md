## 1. 背景与目标

山野茶铺是一家线上茶叶店。v0.1 的目标是上线一个**最小可用的交易闭环**：用户能在电脑和手机上浏览茶品、登录、加入购物车、下单并（模拟）支付，之后可以查看和取消订单。

同时，Sample Mall 是 Tapestry 平台的**标准示例项目**：页面元素带语义化标识、数据确定可复现，用来端到端验证平台的需求管理、迭代、用例设计、UI 自动化、知识库与代码集成能力。

**v0.1 成功标准**

1. 用户在 PC 与 H5 两端都能独立完成「浏览 → 登录 → 加购 → 下单 → 支付」全流程。
2. 售罄、库存不足、未登录、表单错误等异常场景都有明确提示，不出现无提示的失败。
3. 所有验收标准可被自动化用例直接断言（固定文案、固定数据、稳定元素标识）。

## 5. 功能需求

> 每条需求给出**规则**与**验收标准（AC）**。AC 中引号内为界面固定文案。

### REQ-001 双端访问与适配 〔P0 · 双端〕

**规则**
- 同一站点提供 PC 官网（`/`）与移动 H5（`/m`）两套界面，共用账号、购物车与订单数据。
- 移动设备（UA 含 Android / iPhone / iPad / Mobile / HarmonyOS / MicroMessenger）访问 PC 地址时，自动跳转到对应 H5 地址（如 `/product/green-mist` → `/m/product/green-mist`）。
- PC 页脚提供「手机版」、H5 首页页脚与「我的」页提供「电脑版」，手动切换后记住偏好，不再自动跳转。
- PC 浏览器直接访问 `/m` 不跳转。

**AC**
1. 用手机 UA 打开 `/product/green-mist`，落地 `/m/product/green-mist`。
2. H5 点「电脑版」后，再访问 `/cart` 停留在 PC 页面。
3. PC 浏览器访问 `/m` 显示 H5 界面。

### REQ-010 首页与商品列表 〔P0 · 商品〕

**规则**
- 首页依次展示：横幅（标题「来自山野的一杯好茶」，副标题「六款精选茶品 · 产地直发 · 满 ¥99 包邮」）、公告条、分类筛选、商品计数「共 N 款商品」、商品卡片列表。
- 商品卡片展示色块图、名称、价格、库存状态；PC 额外展示一句话卖点和划线原价。PC 每行 3 个，H5 每行 2 个。
- 点击卡片进入商品详情。

**AC**
1. 首页显示「共 6 款商品」，卡片顺序与附录 A 一致。
2. 点击「蜜桃乌龙」卡片，进入 `/product/peach-oolong`。

### REQ-011 分类筛选 〔P1 · 商品〕

**规则**：分类依次为「全部 / 绿茶 / 乌龙茶 / 红茶 / 白茶 / 黑茶」，默认「全部」；选中分类后列表与计数同步刷新；分类下无商品时显示「该分类暂无商品」。

**AC**
1. 点「绿茶」，显示「共 2 款商品」（云雾绿茶、桂花龙井）。
2. 点「全部」恢复 6 款。

### REQ-012 库存状态与促销标识 〔P0 · 商品〕

**规则**

| 库存 | 列表文案 | 角标 |
|---|---|---|
| > 10 | 「有货」 | |
| 1 ~ 10 | 「仅剩 N 件」 | |
| 0 | 「已售罄」 | 「已售罄」 |
| 有划线原价 | 按库存规则 | 「限时特惠」（优先于售罄角标） |

**AC**：蜜桃乌龙显示「仅剩 8 件」；茉莉白茶显示「已售罄」角标；金骏眉红茶显示「限时特惠」角标与划线价 ¥328.00。

### REQ-013 商品详情 〔P0 · 商品〕

**规则**
- 展示：面包屑（PC：首页 / 分类 / 商品详情）、色块图、名称、卖点、价格（含划线原价）、产地、库存「剩 N 件」或「已售罄」、运费说明「满 ¥99 包邮，不满收取 ¥10」、商品介绍、规格参数表（净含量 / 保质期 / 冲泡水温）。
- 数量选择器：± 按钮与直接输入，范围 1 ~ min(99, 库存)，到达边界时对应按钮置灰；小计 = 单价 × 数量，实时更新。
- 加载过程中显示骨架屏（至少 400ms）。
- 售罄商品：「加入购物车」按钮文案变为「已售罄」，与「立即购买」一起置灰。

**AC**
1. 蜜桃乌龙详情：价格「¥89.00」，库存「剩 8 件」；数量加到 8 后「＋」置灰。
2. 数量为 2 时小计「¥178.00」。
3. 茉莉白茶两个按钮均不可点击。

### REQ-014 商品不存在兜底 〔P2 · 商品〕

**规则**：访问不存在的商品 ID，显示「商品不存在或已下架」与「返回首页」按钮。

**AC**：访问 `/product/not-exist` 显示上述文案，点「返回首页」回到首页。

### REQ-020 加入购物车 〔P0 · 购物车〕

**规则**
- 未登录点击「加入购物车」或「立即购买」：提示「请先登录」，跳登录页并携带回跳地址，登录后回到原商品详情。
- 已登录：弹出确认框「确认加入购物车」，内容「<商品名> × <数量>，小计 ¥xx.xx」；点「确认加入」后提示「已加入购物车」，购物车徽标增加对应数量；点「取消」或遮罩关闭不加购。
- 同一商品重复加入时合并数量，单品上限 99 件。
- 售罄商品不可加入（接口返回「商品已售罄」）。
- 购物车数据保存在服务端，按账号隔离，换设备 / 换端登录可见。

**AC**
1. 未登录在蜜桃乌龙详情点「加入购物车」→ 提示「请先登录」→ 登录后回到 `/product/peach-oolong`。
2. 数量 2 加购后，徽标显示「2」。
3. 再加 1 件，购物车中该商品数量为 3。

### REQ-021 购物车 〔P0 · 购物车〕

**规则**
- 列表展示商品色块、名称、单价、数量选择器、小计、删除；顶部「清空购物车」。
- 修改数量立即保存并重算金额。删除和清空需二次确认（「删除商品」/「清空购物车」）。
- 底部汇总：商品合计、运费、应付金额，以及包邮提示（未满 99：「再买 ¥X 即可包邮」；已满：「已满 ¥99，免运费」）。
- 空购物车显示「购物车还是空的，去挑几款好茶吧」与「去逛逛」。
- 「去结算」进入确认订单页；无可结算商品时按钮置灰。

**AC**
1. 购物车只有 1 件蜜桃乌龙：商品合计 ¥89.00、运费 ¥10.00、应付 ¥99.00，提示「再买 ¥10.00 即可包邮」。
2. 数量改为 2：运费 ¥0.00，应付 ¥178.00。
3. 清空后显示空状态。

### REQ-022 购物车失效商品 〔P1 · 购物车〕

**规则**：购物车中商品已售罄、数量超过当前库存或已下架时，该行置灰并显示原因（「已售罄」/「库存不足，仅剩 N 件」/「商品已下架」），不计入合计、不参与结算；把数量改到库存以内即恢复。

**AC**：蜜桃乌龙数量改为 9（库存 8），该行显示「库存不足，仅剩 8 件」，且不计入应付金额。

### REQ-030 登录 〔P0 · 账号〕

**规则**
- 字段：用户名、密码。校验顺序：用户名为空 →「请输入用户名」；密码为空 →「请输入密码」（前端拦截，不发请求）。
- 账号不存在或密码错误统一提示「用户名或密码错误」。
- 提交期间按钮显示「登录中…」且不可重复点击（至少 500ms）。
- 成功后提示「登录成功」，跳转 `redirect` 参数地址，缺省回到当前端首页。
- 页面展示演示账号提示「演示账号：demo　密码：tapestry2026」。
- PC 顶部显示「你好，<显示名>」与「退出登录」。

**AC**
1. 空提交显示「请输入用户名」。
2. demo / 错误密码显示「用户名或密码错误」。
3. demo / tapestry2026 登录后顶部显示「你好，茶客_demo」。

### REQ-031 退出登录 〔P1 · 账号〕

**规则**：PC 顶部、H5「我的」页提供「退出登录」；退出后提示「已退出登录」，清除本地登录态与购物车徽标；若当前页面需要登录，PC 回到首页。

**AC**：在我的订单页退出，回到首页且顶部显示「登录」入口。

### REQ-032 登录态保持与失效 〔P1 · 账号〕

**规则**：登录凭证有效期 7 天，刷新页面或重新打开浏览器保持登录；任何接口返回未登录（401）时自动清除本地登录态。未登录访问需登录页面（购物车、确认订单、订单）时提示「请先登录」并跳登录页，登录后回跳。

**AC**：未登录直接访问 `/orders`，跳转 `/login?redirect=/orders`，登录后回到我的订单。

### REQ-040 立即购买 〔P1 · 交易〕

**规则**：详情页点「立即购买」（需登录）直接进入确认订单页，结算当前商品与所选数量，不经过、也不改动购物车。

**AC**：陈年普洱数量 1 立即购买，确认订单页应付「¥388.00」，购物车内容不变。

### REQ-041 确认订单 〔P0 · 交易〕

**规则**
- 收货信息：收货人（必填，≤ 20 字）、手机号（必填，以 1 开头的 11 位数字）、收货地址（必填，≤ 100 字）、订单备注（选填，≤ 100 字）。手机号默认带出账号绑定手机。
- 校验文案：「请填写收货人」「请填写手机号」「手机号格式不正确」「请填写收货地址」，在对应字段下方显示。
- 商品清单：从购物车进入时为购物车中全部可结算商品；从立即购买进入时为单个商品。
- 金额：商品金额 = Σ 单价 × 数量；**运费：商品金额 ≥ ¥99 免运费，否则 ¥10**；应付 = 商品金额 + 运费。免运费时运费显示「免运费」。
- 按钮「提交订单」，提交中显示「提交中…」。

**AC**
1. 手机号填「123」提交，显示「手机号格式不正确」，未生成订单。
2. 购物车 1 件蜜桃乌龙结算：商品金额 ¥89.00，运费 ¥10.00，应付 ¥99.00。

### REQ-042 提交订单 〔P0 · 交易〕

**规则**
- 提交成功：提示「下单成功」，跳转订单详情；订单状态「待支付」。
- 订单号格式 `SM` + 下单日期 `yyyyMMdd` + 6 位序号，如 `SM20261012000001`。
- 订单保存下单时的商品名称、价格快照，之后商品改价不影响已下订单。
- 从购物车结算的商品在下单后从购物车移除，未结算的失效商品保留。

**AC**：购物车结算下单后，跳转订单详情显示「待支付」，购物车徽标消失。

### REQ-043 库存校验与扣减 〔P0 · 交易〕

**规则**：下单时实时校验库存，任一商品不足则整单失败并提示「「<商品名>」库存不足」，不生成订单、不扣任何库存；成功则立即扣减库存（v0.1 采用下单即扣减）。

**AC**
1. 蜜桃乌龙库存 8，下单 2 件后详情页库存显示「剩 6 件」。
2. 再立即购买 7 件，提示「「蜜桃乌龙」库存不足」。

### REQ-044 模拟支付 〔P0 · 交易〕

**规则**：待支付订单可在订单详情（「立即支付」）或订单列表（「去支付」）发起支付；弹出确认框「确认支付」，内容「订单 <订单号> 应付 ¥xx.xx（演示环境，模拟支付）」；确认后订单变为「已支付」，记录支付时间，提示「支付成功」。非待支付订单不可支付（提示「订单状态已变更，请刷新后重试」）。

**AC**：支付后订单详情显示「已支付」与支付时间，「立即支付」「取消订单」按钮消失。

### REQ-050 我的订单 〔P0 · 订单〕

**规则**
- 入口：PC 顶部「我的订单」，H5「我的」页订单入口（待支付 / 已支付 / 已取消 / 全部订单）。
- 页签：全部 / 待支付 / 已支付 / 已取消；按下单时间倒序。
- 订单卡片：订单号、下单时间（PC）、状态标签、商品、件数、实付金额；待支付订单显示「取消订单」「去支付」。
- 无订单显示「暂无订单」与「去逛逛」。

**AC**：下 2 单并取消其中 1 单后，「已取消」页签只显示 1 单。

### REQ-051 订单详情 〔P1 · 订单〕

**规则**：展示状态、订单号、收货人与手机、地址、备注、商品清单、商品金额、运费、实付金额、下单 / 支付 / 取消时间；只能查看本人订单，他人订单或不存在显示「订单不存在」。

**AC**：用 demo2 访问 demo 的订单详情地址，显示「订单不存在」。

### REQ-052 取消订单 〔P1 · 订单〕

**规则**：仅「待支付」订单可取消；二次确认「取消订单」（按钮「取消订单」/「再想想」）；取消后状态「已取消」，记录取消时间，**回补库存**，提示「订单已取消」。

**AC**：立即购买陈年普洱 1 件后库存为 22，取消订单后库存恢复为 23。

### REQ-060 H5 底部导航 〔P1 · H5〕

**规则**：H5 首页、购物车、我的三个页面底部固定 Tab「首页 / 购物车 / 我的」，购物车 Tab 显示数量徽标；其余页面顶部标题栏带返回按钮，不显示 Tab。商品详情、结算、订单详情的主要操作按钮固定在屏幕底部。

**AC**：H5 加购 1 件后，购物车 Tab 徽标显示「1」。

### REQ-061 H5「我的」页 〔P2 · H5〕

**规则**：已登录显示头像（显示名首字）、「你好，<显示名>」、用户名；未登录显示「去登录」。下方为订单入口、「切换到电脑版」、「退出登录」（仅登录后）。

**AC**：已登录点「待支付」进入 `/m/orders?status=PENDING_PAYMENT`，只显示待支付订单。

## 6. 业务规则汇总

### 6.1 订单状态机

```
            支付（REQ-044）
 待支付 ─────────────────▶ 已支付
 PENDING_PAYMENT            PAID
     │
     │ 取消（REQ-052，回补库存）
     ▼
 已取消 CANCELLED
```

### 6.2 金额与库存

| 规则 | 取值 |
|---|---|
| 包邮门槛 | 商品金额 ≥ ¥99.00 |
| 运费 | ¥10.00 |
| 单品购买上限 | min(99, 当前库存) |
| 低库存阈值 | ≤ 10 件显示「仅剩 N 件」 |
| 库存扣减时机 | 下单成功时扣减；取消订单时回补 |
| 金额精度 | 人民币，保留 2 位小数 |

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 兼容性 | PC：Chrome / Edge 最新版；H5：iOS Safari、Android Chrome、微信内置浏览器 |
| 性能 | 本地环境首页可交互 < 2s；接口 P95 < 300ms |
| 安全 | 口令摘要存储；令牌签名校验在网关完成，下游服务只信任网关注入的用户身份；用户只能访问本人购物车与订单 |
| 可测试性 | 所有交互与断言元素带 `data-testid`，两端同一语义使用同一标识；关键文案固定；数据每次启动重置为附录 A |
| 可观测性 | 各服务提供 `/actuator/health` 健康检查 |

## 8. 系统架构（概要）

前端 Vue 3 单工程双端；后端 Spring Boot 微服务：网关（:8080，路由 + 鉴权）、用户服务（:8081）、商品服务（:8082）、交易服务（:8083，购物车 + 订单，经内部接口调用商品服务扣减 / 回补库存）。详见后端仓库 README。
